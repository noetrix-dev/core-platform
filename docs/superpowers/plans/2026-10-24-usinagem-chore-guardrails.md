# Usinagem: chore de guardrails, plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adaptar tooling e regras do monorepo para o `apps/usinagem` (Postgres + Drizzle), sem o agente editar guardrails.

**Architecture:** O agente altera só o `package.json` do app e gera um patch. Mudanças em `.claude/**` e `.gitignore` são guardrails: o agente escreve o patch em `docs/superpowers/patches/`, e o responsável humano revisa, aplica e commita.

**Tech Stack:** pnpm 9.15.9 (não atualizar), Turborepo, Next 16.3.4 (`next typegen`).

**Spec:** `docs/superpowers/specs/2026-10-24-express-usinagem-erp-design.md` (§9, linha "chore")

## Global Constraints

- Agente nunca edita `.claude/hooks/*`, `.claude/rules/*`, `.claude/settings.json`, `.gitignore`. Entrega patch.
- Sem push. Branch `feat/usinagem-fundacao`.
- Textos em PT-BR, sem travessão.

### Task 2: Patch de guardrails para o humano aplicar

**Files:**
- Create: `docs/superpowers/patches/2026-10-24-guardrails-usinagem.patch`

**Interfaces:**
- Produces: patch aplicável com `git apply`, que altera `.claude/rules/frontend.md`, cria `.claude/rules/usinagem-database.md`, altera `.claude/hooks/block-protected-paths.sh` e `.gitignore`.

- [ ] **Step 1: Montar as mudanças numa cópia temporária, fora da árvore**

```bash
S=$(mktemp -d)
git worktree add --detach "$S/wt" HEAD
cd "$S/wt"
```

Na cópia `$S/wt` (não na árvore de trabalho):

1. Acrescentar ao fim de `.claude/rules/frontend.md`:

```markdown

## Exceção: apps/usinagem

- Tokens da identidade Express (vermelho `#A81915`, grafite `#191919`/`#1A1A1A`, cobre `#B5652E`, fundo `#EEF0EE` com grid blueprint de 28 px) e as variáveis de tema do shadcn/ui vivem em `apps/usinagem/app/globals.css`. Fora disso, a regra de não criar CSS global vale.
- Tipografia: IBM Plex Sans e IBM Plex Mono via `next/font`.
- ERP de balcão: telas de operação são desenhadas para 1280 px e validadas também em 375 px (nada quebra, nada some, alvo de toque de 44 px).
```

2. Criar `.claude/rules/usinagem-database.md`:

```markdown
---
paths:
  - "apps/usinagem/**/*.ts"
  - "apps/usinagem/**/*.tsx"
---

# Database (apps/usinagem)

As regras de Supabase de `database.md` não valem aqui. O usinagem usa Postgres 16 + Drizzle.

- Schema em `apps/usinagem/lib/servidor/db/schema.ts`. Migrations em `apps/usinagem/drizzle/`, geradas por `drizzle-kit generate` pelo responsável humano. Agente nunca cria, edita nem aplica migration.
- Só Postgres local (Docker) ou o serviço do CI. Nunca conectar a banco remoto; `lib/servidor/db/url-local.ts` recusa host que não seja local.
- Acesso a dados pelo query builder do Drizzle. `sql` só como template parametrizado, nunca por concatenação de string.
- Dinheiro em centavos inteiros (`bigint`), nunca float. Quantidade inteira.
- Registro de negócio não é apagado: cancelar e estornar mudam estado e geram evento.
- Operação repetível (remessa, recebimento, NF, movimento de estoque) carrega `chave_idempotencia` única.
- Reserva e movimento de estoque rodam em transação, com `SELECT ... FOR UPDATE` no lote.
- Escrita sensível grava `eventos_auditoria` na mesma transação.
- Permissão e sigilo por campo são checados no servidor (`requirePermissao`, serializadores de `lib/dominio/sigilo`).
```

3. Em `.claude/hooks/block-protected-paths.sh`, antes da linha `  *.env|*.env.*)`, inserir:

```bash
  *apps/usinagem/drizzle/*)
    echo "BLOCKED: '$file' is a Drizzle migration. Migrations are generated by drizzle-kit by the human owner, never edited by Claude Code." >&2
    exit 2 ;;
```

4. Acrescentar ao fim de `.gitignore`:

```
# Fontes privadas da Express (nunca versionar)
docs/express-usinagem/fontes/
```
